# Implementation Plan

## Delivery and branch policy

Deliver usable vertical phases from the agreed specification. Start each phase from clean `main` on its named branch. Commit related changes in order, verify the complete phase, then merge with `git merge --ff-only`. Rebase and repeat checks if `main` changes; never create merge commits or rewrite an already merged phase. Retain commits and verification evidence as the audit trail; delete merged phase branches after verification. Preserve unrelated user files through isolated worktrees. No push, release publication, deployment or paid model execution is included.

### Resolved product decisions and explicit deferrals

1. **Adoption:** concrete changes are approved for implementation; target contracts must not be mistaken for shipped behavior.
2. **Navigation:** Home, Ideas, Goals, Epics, Board, Todos, Calendar, Graph, Workflows, Evolution, Cost, Projects. Personal Settings and installation System are profile popups; project configuration keeps project scope.
3. **Typo/rework:** automatically correct spelling only in unaccepted drafts, preserving meaning/history. Verify changes requested enters human Clarify; unchanged scope returns Ready, changed scope returns Todo then Refine. Success still requires human Approval.
4. **Capacity/locks:** lane quotas cannot increase project shared pools. Board locks persist per project/stable workflow independently of filters/lenses; other workflows may continue.
5. **Home/Projects:** burndown uses remaining leaf-Task count over a selected period with separate scope changes; pie uses open tickets by phase. Projects Tickets includes visible Goal/Epic/Task records with Epic/Goal subsets, excluding protected defaults. Agents means verified running sessions; activity means ticket mutation or agent lifecycle event.
6. **Evolution:** creation-to-Done elapsed time, verified active agent time, separate human-attention request/response counts and optional project-visible human 1–5 ratings. Missing data stays labelled.
7. **Demo:** explicit reset confirmation, verified synthetic provenance/current versions, refusal of non-demo collisions and non-synthetic/human-edited work. Existing-project simulation must use disposable state.
8. **Deferred:** retain worktrees during MVP; compare fresh clones later. Password-hash/PII encryption/key/retention policy belongs to a separate security phase. Parked analysis-budget/pricing choices remain parked. No further product input blocks agreed shell work.
